# 2026-09-15 동시 접속 지연 점검

## 운영에서 확인한 사실

- 정적 사이트와 초기 JS/CSS는 HTTP 200이었다. 인증 없는 API의 401은 정상 인증 거절이며 학생 접속 성공을 의미하지 않는다. 인증된 학생 접속·저장에 대한 운영 QA는 하지 않았다.
- 00:41 UTC `/api/shared-settings` 응답의 `X-School-Function-Region`은 `us-east-1`이었다. Supabase 프로젝트의 실제 지역은 `ap-northeast-2`(서울), 상태는 `ACTIVE_HEALTHY`였다. 함수와 DB의 장거리 통신은 연속 RPC 지연에 기여할 수 있다. 이 사실만으로 CPU 부족이나 수용 인원 한계를 확정하지 않는다.
- 누적 DB 통계: scoped 조회 6,748회, 평균 282.0ms, 최대 7,938.4ms. 전체 조회 2,590회, 평균 474.0ms, 최대 7,614.6ms. 저장소 요청 제한은 8초다. 누적 최대값은 이전 장애도 포함하므로 이번 장애의 현재 응답 시간으로 해석하지 않는다.
- 첫 연결 상태 표본에는 활성 쿼리 7개와 최대 27초가 관측됐다. 해당 SQL 종류는 확인하지 못했다. 후속 표본에는 활성 쿼리나 잠금 대기가 없었다. CPU·메모리 부족과 연결 포화는 확인되지 않았다.
- 기존 metadata 함수, scoped 함수의 `jit=off`, 조회 인덱스는 이미 설치돼 있었다. DB 내용·스키마·환경변수는 변경하지 않았다.

## 소스 수정

- `api/shared-settings.ts`: 정상적인 현재 시즌의 책장 등록에서 최초 학생 scoped 조회를 재사용한다. DB 요청이 5회에서 3회로 줄었다. 월이 바뀌면 기존 시즌 정산 및 학생 지갑·장부 재조회 경로를 유지한다. 잘못된 시즌 상태, CAS 충돌, 저장 후 확인 조회와 멱등성 계약도 유지한다.
- `src/server/todayFriendRepository.ts`, `api/today-friend.ts`: 같은 프로세스에서 동시에 진행 중인 같은 날짜의 학생 GET 공통 계획 조회를 공유한다. URL·서버 자격·날짜가 다르면 공유하지 않는다. 완료·실패 후에는 보관하지 않는다. 학생별 제출 조회와 저장 전 계획 검사는 공유하지 않는다. 여러 Netlify 인스턴스 사이의 전역 요청 통합은 아니다.

## 로컬 검증

실제 API 코드를 로컬 HTTP 서버에서 호출하고 합성 upstream을 사용했다. 운영 DB에 부하를 가하거나 실제 학생 기록을 변경하지 않았다.

| 오늘의 친구 23명 동시 GET, 공통 계획 RPC | 23회 | 1회 |
| 위 요청의 학생 제출 조회 | 23회 | 23회 |

- HTTP로 감상문과 pageCount 0을 포함한 책장 등록 200, 같은 요청 재전송 200, 중복 보상 없음, 이미 찬 자리 409, 다른 학생 잔액 보존을 확인했다.
- 오늘의 친구 23명에게 각자의 미션 반환, 미등록 요청 401, 날짜·자격별 격리, 실패 전파 및 새 조회 복구, 저장 전 독립 조회를 검증했다.
- 관련 테스트 58개 통과. `npm run build` 통과. `git diff --check` 통과.
- 전체 `npm test`: 1,293개 통과, 2개 실패, 1개 skip. 실패한 `tests/api/storageCommands.test.ts` 편지 보존 검사 2개는 수정 전 HEAD의 핸들러를 사용해도 동일하게 재현됐다(2≠3, 23≠25). 이번 변경으로 해결한 것으로 표시하지 않는다.
- `npm run lint`: 기존 `src/lib/studentPet.test.ts:204`의 불완전한 `StudentEconomyState` fixture로 TS2740. 이번 변경 파일의 새 타입 오류는 없었다.

## 사용자 운영 작업

1. Netlify `Project configuration → Build & deploy → Continuous deployment → Functions region`에서 Tokyo(`nrt`) 선택 가능 여부를 확인한다. 지역 변경은 Pro/Enterprise에서 제공된다. 요금제 변경은 별도 판단 사항이다.
2. 지역 변경이 가능하면 사용자가 직접 변경하고 수정 소스를 배포한다. Netlify 지역 설정은 새 배포에 적용되므로 이후 실제 응답의 `X-School-Function-Region`도 확인한다.
3. 새로 연 학생 화면에서 조회, 오늘의 친구, 책장 등록을 확인한다. 수업 중 API별 오류율·응답 시간과 동일 시간대 Supabase CPU·메모리·연결 지표를 함께 확인해야 용량 증설 필요 여부를 판단할 수 있다. 정적 이미지가 포함된 전체 요청 성공률로 판단하지 않는다.

Netlify 지역 설정 근거: https://docs.netlify.com/build/functions/configuration/#region (2026-09-15 확인).

Codex는 운영 배포나 지역 설정 변경을 실행하지 않았다. 운영 접속 장애의 해결 완료를 선언할 수 없다.
