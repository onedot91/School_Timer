# 강아지 직원 적용 검수

## 결과

참고 이미지의 크림 얼굴, 갈색 처진 귀, 꽃무늬 산호색 두건과 앞치마를 코드 기반 픽셀 직원에 적용했다. 기존 등록부와 차 세트를 유지하며 등록대 직원 상호작용과 700ms 책 전달을 연결했다.

## 실제 브라우저

- 격리 mock 검수 페이지에서 직원 E → 기존 등록 창 → 취소/다시 열기 → 기존 책 받기를 조작했다.
- 전달 중 창 비활성 이벤트로 멈춘 뒤 여러 번 상태를 읽어 receive, 직원 시간, 고양이 상태가 유지됨을 확인했다. 활성 이벤트 뒤 정상 완료했다.
- 운반 중 E 6회 입력에도 모달이나 추가 책이 생성되지 않았으며 “들고 있는 책을 먼저 꽂아 주세요” 안내를 확인했다.
- 받은 책을 슬롯51에 배치한 뒤 같은 방문에서 등록대로 돌아와 새 제목/작가/감상을 입력했다. 확인 후 등록대 앞 접근과 두 번째 책 운반 완료를 확인했다.
- 100권 상태에서 직원 등록 창이 “100자리가 모두 찼어요. 꽂힌 책은 읽을 수 있어요.”를 표시했다.
- 전달 0/450/900ms 및 동작 줄이기 프리뷰를 실제 렌더러에서 표시하고 전체 화면 이미지로 보관했다. 실제 전달 정지 프레임은 별도 Canvas 이미지로 보관했다.
- 사용자 책방 화면에서 innerWidth1280, innerHeight800, document scrollWidth1280, scrollHeight800을 확인했다. Canvas는 (16,24),1248×752. 직원/등록부/차가 겹치지 않고 화면 밖 잘림이나 불필요한 문서 스크롤이 없다. 임시 viewport 설정을 복원했다.
- 실제 화면과 검수 페이지의 마지막 error/warn 로그는 모두 빈 배열이었다.

## 검증 한계

접근 경로를 강제로 막는 상황과 운영체제의 동작 줄이기 설정 전환은 실제 브라우저에서 별도로 재현하지 않았다. 막힘 복구는 코드 검토, 동작 줄이기는 도메인 검사와 개발 프리뷰로 확인했다. 실데이터 등록/저장은 사용하지 않았다.
