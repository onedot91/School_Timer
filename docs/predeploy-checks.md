# 배포 전 저장 검증

배포 전에 프로젝트 루트에서 실행한다.

```bash
npm run verify:predeploy
```

타입 검사 → 기본 테스트 → 실제 PostgreSQL 저장 회귀 테스트 → 프로덕션 빌드를 순서대로 실행하며, 실패하면 중단한다. 이 명령은 배포하지 않는다.

저장 회귀 테스트만 실행하려면 `npm run test:storage`를 사용한다. 설치된 `initdb`, `pg_ctl`, `psql`이 필요하며 자동 설치하지 않는다. 각 테스트는 임시 디렉터리에 Unix 소켓 전용 PostgreSQL을 만들고 합성 데이터만 사용한다. 운영 DB 연결 정보는 사용하지 않으며 테스트 종료 시 해당 서버를 종료한다. 임시 데이터와 로그는 원인 확인을 위해 남긴다.

필수 검증은 경매의 낙찰자·낙찰가 변경, 타 학생 잔액 변경, 중복 차감 방지, 실패 게시판 글·도장 보존, 중첩 교사 설정 저장, 허용 범위 밖 쓰기 차단이다. 테스트 누락·건너뜀·실패도 검증 실패로 처리한다. 기존 `verify:release` 검증에도 이 저장 회귀 테스트를 포함한다.

동시 저장 부하는 `npm run test:storage:load`로 검증한다. 임시 PostgreSQL에서 실제 `/api/shared-settings` 핸들러를 실행하며 교사 설정 저장 1건과 학생 23명의 입찰·실패 글 저장을 겹쳐 실행한다. 합성 글 69건(타 학생의 도장 포함), 학생별 통화 내역 100건, RPC당 지연 40ms를 사용한다. 지연은 `CLASSROOM_RPC_DELAY_MS`로 조정할 수 있다.

이 검사는 낮은 입찰가의 정상 거절과 저장 실패를 구분하며, 기존 글·도장 보존, 실패 글 23건 및 보상, 낙찰 6건의 차감, 성공 요청 재전송 시 중복 차감·보상 방지, 원장과 잔액 일치를 확인한다. 오류가 있으면 종료 코드 1을 반환한다. 검증용 재전송·낙찰은 부하 응답 시간과 조회량 집계에서 제외한다. 로컬 측정에는 `psql` 프로세스 실행 비용이 포함되며 운영 Vercel·Supabase 응답 시간을 대신하지 않는다.
