### 추가로 확인한 코드 결함과 수정

금융 거래의 복구는 자동 재결제를 금지하는 `confirm-only` 모드다.
기존 복구 러너는 자동 쓰기가 가능한 요청만 일시 오류 재시도 대상으로 삼아,
금융 거래의 안전한 영수증 GET까지 한 번의 연결 오류에서 멈췄다.
아직 영수증이 생성되지 않은 `unknown` 응답도 즉시 중단해서 늦은 확정을 놓칠 수 있었다.

- 금융 거래 영수증의 일시 오류·미확정 응답은 기존 점진적 대기를 이용해 최대 5회 확인한다.
  같은 요청 ID로 조회하며, 자동 POST는 실행하지 않는다. 오프라인 동안은 횟수를 쓰지 않는다.
- 401/403/409는 자동 반복하지 않고, 429의 서버 대기 시간을 유지한다.
- 최초 거래 응답 유실 후 오프라인으로 감지되면 즉시 영수증 조회를 소진하지 않는다.
  진단에는 실제 조회 횟수를 기록한다. 저장 초안과 기존 오류 알림은 보존한다.
- 복구 오류의 기능은 현재 화면 대신 원래 요청에서 결정한다.
- 저장 확정 후 화면 새로고침만 실패한 경우 저장 완료 증거를 보존하며 잔액을 기본값으로 바꾸지 않는다.

이는 연결 복구 후 결과 확인이 조기에 중단되는 결함의 수정이다.
물리적 네트워크 단절이나 오전 DB 지연 원인을 제거했다는 의미는 아니다.
운영 반영 뒤에는 새 배포의 요청 ID와 발생 시각을 기준으로 재발 여부를 확인해야 한다.
이미 접수된 오류는 이후 저장이 확인되어도 교사의 확인 전까지 남는다.
