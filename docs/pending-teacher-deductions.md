# 차감 대기와 자동 차감

잔액 부족 시 보유 고마를 일부 차감하지 않고 요청 금액 전액을 `studentEconomy[학생번호].pendingDeductions`에 기록한다. 보유 고마, 예금 원금과 증권사 투자금의 합계가 충분해지면 등록 순서대로 전액 차감한다. 대출 한도는 계산에 포함하지 않는다. 실제로 입금된 대출금은 보유 고마에 포함된다.

학생 홈의 잔액 카드에 `차감 대기 10고마` 배지가 표시된다. 누르면 금액·사유와 자동 차감 조건을 확인할 수 있다. 교사 고마 설정에는 대기 학생과 사유가 표시된다. 대기 등록과 실제 차감 시 각각 안내 편지가 저장되며, 배지는 대기가 모두 처리되면 사라진다.

## 운영 적용 순서

현재 변경은 소스와 SQL 준비까지이며 운영 데이터에는 적용하지 않았다. 14번 학생의 실제 대기 10고마도 아직 등록하지 않았다.

1. School_Timer Supabase SQL Editor에서 `supabase/storage_pending_deductions.sql`을 실행한다. 기존 저장 체계가 활성 상태여야 한다. SQL은 기존 함수의 수정 위치를 확인하며, 알 수 없는 버전이면 `STORAGE_PENDING_PATCH_VERSION_MISMATCH` 오류로 전체 변경을 취소한다. 학생·익명 역할에 함수 실행 권한을 추가하지 않는다.
2. 이 소스를 사용자가 Vercel에 배포한다. 기존 운영 파일을 재배포하면 대기 필드나 UI가 유실될 수 있으므로 새 버전을 사용한다.
3. 교사 화면의 **화폐 → 개인**에서 **14번 / 10고마 / 크롬북 안 넣어두고 감**을 입력하고 저장한다. 당시 보유 고마＋예금이 10고마 미만이면 `대기 등록`, 충분하면 즉시 차감된다. 앞서 처리된 13·17·19번은 다시 선택하지 않는다.
4. 14번 조회와 교사 대기 내역을 확인한다. 같은 작업을 다시 등록하면 별도의 차감 요청이 되므로, 저장 응답이 불분명한 경우 기록부터 확인한다.

자동 처리는 브라우저 타이머가 아니라 기존 원자적 저장 트랜잭션에서 실행된다. 교사 증감·학생 보상·은행 송금·예금 변경 등은 공통 저장 경로를 거치며, 직접 보상 RPC도 공통 지갑 함수에서 처리한다. 차감·예금 갱신·원장·안내 편지는 같은 트랜잭션에서 반영된다. 새로운 차감 요청 ID와 별도의 자동 처리 ID로 재시도 시 중복 차감을 막는다.

SQL 적용 후 과거 저장 함수 SQL을 덮어써서 다시 실행하면 자동 처리 연결이 사라질 수 있다. 저장 함수 변경 시 이 파일을 마지막에 적용하고 격리 검증을 다시 수행한다.

## 로컬 테스트 창

```bash
npm run dev -- --port 3014 --strictPort
```

`http://localhost:3014/dev/deduction-review.html`은 개발 서버의 mock 모드에서만 열린다. React의 실제 학생 홈·배지·확인창과 실제 도메인 함수를 사용하며, 가짜 데이터는 메모리에만 보관한다. 운영 API와 localStorage를 사용하지 않는다.

교사 검수는 `?teacher=1`을 붙여 열 수 있다. 이 별도 모드는 해당 로컬 개발 origin의 가짜 학급 저장소를 초기화하고 실제 교사 화면을 연다. 운영 API를 사용하지 않는다.

- 초기 상태: 보유 2고마, 대기 10고마, 사유 ‘크롬북 안 넣어두고 감’.
- `5고마 지급` 한 번: 보유 7고마, 대기 유지.
- 두 번: 자동 차감 후 보유 2고마, 대기 해제, 차감 기록 1건.
- 이후 지급: 이미 처리한 대기 금액을 다시 차감하지 않는다.
- `초기화`: 처음 상태로 돌아간다.

## 검증

```bash
npm run lint
npm test
npm run build
```

실제 PostgreSQL 검증은 이번 작업의 임시 Unix socket만 허용한다. 설치된 `initdb`, `pg_ctl`, `psql`을 사용하며 새 패키지를 설치하지 않는다.

```bash
STORAGE_PENDING_PSQL_TEST=1 \
PGHOST=/private/tmp/school-pending-pg.<고유값> PGPORT=55487 \
node --import tsx --test tests/storage/pendingDeductions.integration.test.ts
```

가짜 학급의 혼합 차감/대기, 저장 영수증 재시도, 다른 학생 원본·비공개 편지 보존, 동시 지급, 전액·등록 순서 처리, 예금 전용 차감, 주간 보상 RPC, 원장 일치, 함수 권한, 점검 모드 거절을 검사한다. 운영 학생 데이터는 검증에 사용하지 않는다.

DB 함수 권한 설정 참고: [Supabase 공식 문서](https://supabase.com/docs/guides/database/functions).
